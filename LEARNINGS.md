# Learnings

## Stage 0 — Skeleton & local infra

- **DSN scheme mismatch between SQLAlchemy and a raw driver.** Used `postgresql+asyncpg://...` as the connection string, which is SQLAlchemy's own URL convention for telling itself which driver to load. The code was calling `asyncpg.connect()` directly (no SQLAlchemy involved), and `asyncpg`'s DSN parser only accepts a plain `postgresql://` scheme — the `+asyncpg` suffix broke it. Lesson: a connection-string format is specific to whatever library actually consumes it; copying one library's URL convention into another's call doesn't work just because they look similar.
- **`localhost` doesn't mean the same thing inside a container.** Early version of the health check connected to `localhost`, which worked when run outside Docker (because Compose also published Postgres's port to the host) but failed once the API itself ran *inside* its own container — each container has its own network namespace, and `localhost` there means "this container," not "the other one." Inside a Compose network, you reach another service by its service name (`db`), not `localhost`.
- **`.gitignore` applies hierarchically, not just at the root.** A `.gitignore` file in a subdirectory only governs paths under that subdirectory — it doesn't need to be merged into a single root file to work. Git resolves the effective ignore rules per path by walking up from wherever the file lives.
- **Hand-editing `pyproject.toml` doesn't update `uv.lock`.** Removing a dependency line directly in `pyproject.toml` leaves the lockfile stale — it still has the old resolved versions baked in. Running `uv sync` (without `--frozen`) re-resolves and rewrites `uv.lock` to match what's actually declared.
- **`uv init` initializes its own git repo if none exists in a parent directory.** This created a nested `.git` inside `apps/api` before the monorepo root had one — a real problem, since once the root became its own repo, Git would have treated `apps/api` as a submodule-style gitlink instead of tracking its actual files.
